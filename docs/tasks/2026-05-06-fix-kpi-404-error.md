# Task: Fix 404 Error in KPI Calculation API

- **Date**: 2026-05-06
- **Status**: Completed
- **Source**: User report of 404 error on POST `http://localhost:3000/id/api/kpi-monthly-results`

## 🎯 Goal

Resolve the 404 error when making API calls with a locale prefix (e.g., `/id/api/...`) by ensuring the middleware is correctly named and configured to handle these rewrites.

- [ ] **Phase 2: Core Implementation**
  - [x] Rename `proxy.ts` to `middleware.ts` in the root directory.
  - [x] Update the exported function name from `proxy` to `middleware` to follow Next.js conventions.
  - [x] Verify that the `matcher` in `middleware.ts` correctly includes both localized and non-localized API paths.
- [x] **Phase 3: Testing & Verification**
  - [x] Test the KPI calculation again from the UI.
  - [x] Verify that the request to `/id/api/kpi-monthly-results` is successfully rewritten to `/api/kpi-monthly-results`.
  - [x] Ensure that auth redirects and internationalization still work as expected.

## 🛠️ Technical Details

- Files affected:
  - `proxy.ts` -> `middleware.ts`
- Logic:
  - The middleware uses a regex to match `/en/api/...` or `/id/api/...` and rewrites them to `/api/...`.
  - It also handles session validation for non-auth API routes.

## 📝 Notes & Discoveries

- The project previously documented using `proxy.ts` instead of `middleware.ts` for some reason, but Next.js requires the file to be named `middleware.ts` (or `src/middleware.ts`) to function automatically.
